`@truefoundry/trueforge-ui` provides a production-ready agent chat experience as a single, reusable React component. TrueForge ships this full chat UI with the server — browse agents, stream responses, approve tools, connect MCP OAuth, and manage Settings — and publishes the same experience as `@truefoundry/trueforge-ui` so you can embed it in your own React app.

Key Features:

- **Agent Modes** - Chat with a single agent, browse an agent library, or allow users to create and compose new agents.
- **Chat** - Supports streaming responses, session history, tool calls with approval workflows, and file attachments.
- **Themes** - Includes built-in themes for Claude, ChatGPT, Gemini, and TrueFoundry, with support for creating custom themes.
- **Layouts** - Supports full-screen layouts with a sidebar or drawer, as well as embedded layouts with side-docked or floating widgets.
- **Integration Settings** - Configure models, MCP servers, skills, and sandbox environments.
- **Server Configuration** - Choose between TrueForge, a fully custom server, or TrueFoundry.

## Adaptive controls and current-information search

The composer exposes a **/ Controls** palette for both draft agents and saved (immutable) agents. You can also type commands directly at the start of a message. Recognized control lines are removed from model-visible user text, validated by the server, stored in the root thread's durable capability state, and projected back into the system instruction as user-provided preferences. The original turn input remains available in the public turn record.

| Command | Effect |
| --- | --- |
| `/model <provider/model>` | Use a configured model for this and later turns. `/model clear` restores the agent model and clears model-specific effort. |
| `/effort <value>` | Set an effort advertised by the effective model. `/effort clear` removes the override. |
| `/goal <text>` | Set a durable goal. `/goal clear` removes it. |
| `/plan` or `/plan <text>` | Request planning mode or provide a plan. `/plan clear` disables it. |
| `/context add <text>` | Append bounded, untrusted user context. `/context clear` removes all entries. |
| `/task <text>` | Append a deterministic task. `/task clear` removes all tasks. |
| `/request <text>` | Record the explicit current request. `/request clear` removes it. |
| `/completion <text>` | Set verification criteria. `/completion clear` removes them. |

Only recognized leading command lines are controls; ordinary text and file attachments are preserved. Invalid, oversized, unknown-model, and unsupported-effort requests fail before the turn is committed. Controls persist across later turns and forks. They never override system instructions, tool policy, approvals, authentication, sandbox limits, or host safety policy.

When the server has executable web search configured, the composer shows **Web search: available** beside **Tools**, and the agent receives the `web_search` tool. Configure Brave Search only on the server:

```bash
WEB_SEARCH_PROVIDER=brave
BRAVE_SEARCH_API_KEY=your-host-only-key
WEB_SEARCH_TIMEOUT_MS=15000
WEB_SEARCH_MAX_RESULTS=10
```

The key is never placed in AgentSpec, capability responses, tool arguments, or browser state. Search is disabled by default. Dynamic subagents can choose only from the server's bounded configured-model catalog and retain the parent's tool and sandbox authority.
